# Security test report

Date: 28 October 2026. Verdict: **FAIL / production blocked**. Severity expresses release priority, not a formal CVSS score. Tests used synthetic records only. Failures below were not repaired as part of this audit.

## Reproduced authorization failures

Evidence: `evidence-probes.json`, generated by `run_checks.py probes`. These tests assert the secure outcome and intentionally remain red until fixed.

### SEC-01 — High: native private media lacks object authorization

[base/views.py:8847](C:/Users/DELL/Desktop/HRIS/base/views.py:8847) streams a known non-public media path after an authentication/JWT check, without resolving the owning candidate/employee/document and checking the reader's object access. A synthetic unrelated employee downloaded a synthetic CV: **HTTP 200**, expected 403/404. Hidden-path and path-traversal protections do not establish ownership. The current restricted PeopleHub route tree omits native `/media/`, which reduces exposure there; the failure applies wherever the full native PeopleOps media handler is reachable. It is not a claim of unauthenticated CV access.

Required fix: domain-aware authorization before streaming; deny ambiguous/unowned private files; cover same-company unrelated employees, foreign companies, applicant/staff session separation, JWT readers, historical versions and revoked users. Existing private TVG download endpoints should not be weakened. Candidate profile photos are also public by prefix in this handler; explicitly review whether that is intended.

### SEC-02 — High: native Candidate detail bypasses recruitment permission

[CandidateGetUpdateDeleteAPIView](C:/Users/DELL/Desktop/HRIS/horilla_api/api_views/recruitment/views.py:316) uses `IsAuthenticated` for GET and resolves the object independently of the permission-filtered list. An employee with no `recruitment.view_candidate` permission received **HTTP 200** for another candidate. The test invokes the real DRF view; it does not establish public network reachability. Keep the broad HR API restricted until fixed.

Required fix: share list/detail tenant and object policy, minimize serializer fields, and audit adjacent Recruitment/CandidateDocument detail endpoints for the same pattern. Test low-privilege same-company users, not just cross-company users or anonymous requests.

### SEC-03 — High: internal application API is not constrained to its configured employer

[application_status](C:/Users/DELL/Desktop/HRIS/tvg_careers/application_api.py:446) filters by Person UUID without `TVG_LEGAL_EMPLOYER_ID`. [withdraw_application](C:/Users/DELL/Desktop/HRIS/tvg_careers/application_api.py:474) similarly selects application/person without employer scoping. With a valid synthetic service token configured for company A and known synthetic company-B identifiers:

- Status returned one company-B application instead of none.
- Withdrawal returned **HTTP 200** and changed company B's application; expected 404 and no change.

This is a service-boundary/confused-deputy exposure requiring a valid application token and target identifiers, not an anonymous public exploit. Candidate-side ownership tests do not replace receiver-side employer isolation.

Required fix: constrain both Person and opening/recruitment ownership consistently for read, idempotent retry and mutation; fail closed for inactive/mismatched identity; centralize the policy and extend the four regression probes into maintained CI.

## Other blocking security findings

Minimized machine evidence is `evidence-dependencies.json`: package/version/advisory/fix metadata only, excluding third-party descriptions and proof-of-concept payloads. The scan reported 12 entries, with repeated IDs, normalized to 9 distinct advisory IDs across 5 packages. This is an installed-environment scan, not a scan of the eventual container image or an exploitation assessment.

### SEC-05 — High: production configuration guards fail unsafe inputs

`evidence-configuration.json` records three failed negative checks. The private secret validator accepts a one-character signing key and a mixed host list containing `*`. CareerHub with `HORILLA_ENV=production` plus `DEBUG=1` imports without rejecting the combination and sets an insecure session cookie. Source: [private guards](C:/Users/DELL/Desktop/HRIS/horilla/settings/security.py:32), [public production check](C:/Users/DELL/Desktop/HRIS/horilla/settings/careerhub.py:277).

The supplied production Compose sets `DEBUG=0`; this is a fail-closed guard weakness, not evidence that the live deployment has DEBUG enabled. Required fix: reject production DEBUG, enforce adequate generated secret strength, reject any wildcard host entry, and run deployment checks for all three actual runtime settings with sanitized effective-setting evidence. Validate independent secrets/cookies and least-privilege DB grants. Do not log secrets while doing so.

### SEC-06 — High: uploads need production quarantine/scanning

Candidate upload inspection rejects several dangerous formats/content patterns but explicitly is not antivirus. Verification defaults to a disabled scanner that leaves files pending, safely blocking review. `FakeCleanScanner` is selectable without a production-mode guard in the scanner loader. Require a real approved scanner, quarantine/timeout/failure behavior, a hard production rejection of fake scanners, and consistent scan gates for CVs, legal uploads and presentations. Validate controlled downloads after scan and before approval. Do not unblock production with the fake scanner.

### SEC-07 — High: authentication tokens can enter access logs

CareerHub verification and reset tokens are URL path components. [Gunicorn access logging](C:/Users/DELL/Desktop/HRIS/docker/gunicorn.conf.py:35) includes the full request line and referrer; nginx has no token-route access-log redaction in the supplied configuration. App JSON redaction alone does not cover those logs. This is a source-confirmed logging path, not a claim that real tokens were collected during the audit.

Required fix: redact sensitive path/query components and referrers in every hop (including edge/proxy/APM), constrain log access/retention, and regression-test canary-token absence. Complete full-history secret scanning and incident/rotation review; older CI comments acknowledge historical credential exposure, but no rotation completion evidence was provided.

## Controls that passed focused tests

- Public registration/password validation, CSRF, generic recovery/duplicates, verification expiry, session rotation/logout and password-reset invalidation.
- Public documents owner-scoped; separate candidate principal cannot acquire staff permissions; public route allowlist excludes HR/admin.
- PeopleHub directory allowlist, intern isolation, supervisor direct-report scope and cross-company denial.
- TVG approval gates, immutable document/report versions, human decisions, optional AI advisory boundary, duration exception workflow and offboarding mandatory-task gates.
- Activepieces callback signatures/timestamp window, bounded payloads, duplicate-key conflicts, retry/dead-letter/replay/cancellation and explicit human approval with synthetic transport. Service callbacks update execution records, not arbitrary business tables.
- Selected native hidden-media-path, tenant, leave-tab, helpdesk and export/access regression tests: 51 pass.

These are test-specific passes; they do not negate SEC-01 through SEC-07. Existing email/provider/database credentials, actual firewall/Cloudflare policies, SMTP delivery, penetration resistance under load, and production monitoring were not exercised.
